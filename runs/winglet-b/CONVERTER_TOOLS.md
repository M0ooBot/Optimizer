# Airfoil Converter tools the winglet work needs

A running list of what the winglet study needs from the Converter, kept as the study finds it. The Converter now serves these as MCP tools ([PR #10](https://github.com/Trying-to-Fly/Airfoil-Converter/pull/10), pinned at [27ffb86](https://github.com/Trying-to-Fly/Airfoil-Converter/tree/27ffb8627d727c503214b8481dc2b50117cf7728)). [Converter MCP server](#converter-mcp-server) below says how to start it. The study's own build still uses the Converter at [d77bbdf](https://github.com/Trying-to-Fly/Airfoil-Converter/tree/d77bbdf45a8c0aa92efbc2a3d3007cfe4f904105) and its own laws in [phase0_winglet](../../src/planeopt/phase0_winglet.py); moving it onto these tools is separate work.

| Tool | Winglet need | Converter MCP tool (27ffb86) |
| --- | --- | --- |
| Blunt trailing edge, keep chord | Every section ends in a 0.4 mm trailing edge | **Yes**: `blunt_trailing_edge` (core `geometry.cut_trailing_edge`). Also returns the cut station, cut chord and regrow scale, so a caller can build a smooth family by chord. The cut is still made on the polyline, so the station is continuous but only piecewise smooth in the thickness. |
| Place a section in any plane | Section planes rotate through the bend | **Yes**: `place_section`, given a leading-edge point, chord direction, up direction, chord and twist about a chord-fraction pivot (positive is nose up). It puts the true nose on the leading-edge point and can write the curve. |
| Split a section into camber and thickness | The morph works on camber and thickness, not points | **Yes**: `split_section`, from the true nose on the spline SolidWorks draws, on a common cosine grid. Camber is measured square to the chord line, not to the camber line as NACA do: up to 0.11 % chord off NACA's mean line near the nose for a 2412. This keeps a blunt trailing edge exactly the thickness it was cut to. |
| Morph between two sections | SD7037 into a symmetric section through the bend, with the trailing edge held in mm | **Yes**: `morph_sections` blends camber and thickness by a weight, then re-adds a trailing-edge ramp held at a thickness in mm at a given chord. Can save the result as a `.dat` file. |
| Analytic and UIUC profiles | The target section (NACA 0010 thickness here) | **Yes**: `naca4`; UIUC `.dat` files (Selig and Lednicer) read through every section tool; `fetch_uiuc` downloads one by name when the server is started with `--allow-network`. |
| Leading-edge radius of a section | The 0.4 mm rule applies to leading edges when the trailing edge is blunt | **Yes**: `nose_radius`, from the spline through the points, plus the radius normal to a swept leading edge (r / cos sweep). It measures the curve SolidWorks would draw, so it depends on the point count (NACA 0012 at 161 points per surface: 0.4 % under the analytic value). |
| Edge curves drawn from sweep laws | The leading and trailing edges are drawn; the chord follows from them | **Through `build_law`**: the caller evaluates its own laws and passes each station's leading-edge point, directions and chord. The edges are written through those stations. There is no sweep-law input as such. |
| Sections and curves along a law | Dozens of sections through the bend, with leading-edge, trailing-edge and skin guide curves | **Yes**: `build_law`. Stations as JSON (placement plus a profile or a morph weight between two profiles) give section curves, LE and TE curves, and surface guides at the window's chord fractions, plus a loft plan. Guides have one point per section, so space the stations closely through the bend. Not recorded in a Converter project. |
| Loft in SolidWorks through those sections and guides | Stage 2 onward | **SW-Agent's job** (decided 2026-11-25). The server stops at curve files and a loft plan (profiles in order, guides, joins, feature to file). SW-Agent imports and lofts them. A loft through section planes rotating through 75° is still untested. |

## Converter MCP server

The repository's [.mcp.json](../../.mcp.json) registers it for Claude Code as `airfoil-converter`. It runs from the pinned commit through `uvx`, in its own environment, because it needs `mcp` 2.x while the Optimizer pins 1.x. Its workspace is [converter/](converter/): every file it writes lands there. It can also read [aircraft/phase0_sd7037](../../aircraft/phase0_sd7037/), which holds `sd7037-il.csv`. Paths are taken relative to the workspace, so reach that file as `../../../aircraft/phase0_sd7037/sd7037-il.csv`, or by the absolute path `converter_info` reports. From a terminal, at the repository root:

```sh
uvx --from "airfoil-converter[mcp] @ git+https://github.com/Trying-to-Fly/Airfoil-Converter@27ffb8627d727c503214b8481dc2b50117cf7728" airfoil-converter-mcp --workspace runs/winglet-b/converter --read-root aircraft/phase0_sd7037
```

Add `--allow-network` to offer `fetch_uiuc`. For Codex, put the same command and arguments under `[mcp_servers.airfoil-converter]` in `~/.codex/config.toml`. Codex starts servers from wherever it was launched, so give it absolute paths there.

Start with `converter_info`: it reports units, axes, every setting and the chord-frame conventions. The full tool reference is the Converter's [README](https://github.com/Trying-to-Fly/Airfoil-Converter/blob/27ffb8627d727c503214b8481dc2b50117cf7728/README.md#mcp-server). To move to a newer Converter, change the commit in `.mcp.json`, here and in the table header.
